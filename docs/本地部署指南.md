# 安装部署指南
### 一、前置条件
#### 1、已获取到部署安装包 AgentBuilder.tar.gz
* 部署安装包打包方法参考[源码编译构建指导.md](../docker/%E6%BA%90%E7%A0%81%E7%BC%96%E8%AF%91%E6%9E%84%E5%BB%BA%E6%8C%87%E5%AF%BC.md)

### 二、第三方组件依赖
* mysql
* redis
* obs

### 三、在线部署方案
#### 1、适用场景
服务器可以访问镜像仓库，推荐直接从 GHCR 或 Docker Hub 拉取镜像。当前在线部署推荐使用 Docker Compose 和 `deploy-server.sh all`，脚本会拉取镜像、初始化基础设施、启动服务并执行启动后验证。

#### 2、环境要求
* Docker 20 or later
* Docker Compose 1.28 or later，或 Docker Compose v2
* bash
* curl（用于启动后的健康检查）

#### 3、安装流程
![dockerComposeInstall.png](images/dockerComposeInstall.png)

#### 4、安装步骤
##### 步骤 1、解压安装包：
```bash
tar -zxvf AgentBuilder.tar.gz
cd compose
```

##### 步骤 2、配置镜像仓库
编辑 `.env.server`。默认使用设置`IMAGE_SOURCE=ghcr`, 使用 GitHub Container Registry。

如果镜像仓库需要认证，可在 `.env.server` 中填写：

```env
GHCR_USERNAME=
GHCR_TOKEN=
DOCKERHUB_USERNAME=
DOCKERHUB_TOKEN=
```

##### 步骤 3、修改服务配置
继续检查 `.env.server` 中的数据库、Redis、MinIO、端口和 TLS 配置。单机 Docker Compose 部署默认会启动内置 MySQL、Redis、MinIO。

脚本内部固定使用 `docker-compose-server.yml` 和 `.env.server`，不会误用同目录下的 `docker-compose.yml`。

##### 步骤 4、一键启动

```bash
./deploy-server.sh all
```

该命令会拉取镜像、执行基础初始化、启动全部服务、等待容器健康/运行状态，并验证以下地址：

```text
http://localhost/openjiuwen/
http://localhost/actuator/health
http://localhost:31113/v1/health
```

##### 步骤 5、安装后验证
在浏览器中输入以下地址并访问：

```text
http://节点ip/openjiuwen/#/home/overview
```

也可以使用脚本查看状态或日志：

```bash
./deploy-server.sh status
./deploy-server.sh logs
./deploy-server.sh verify
```

### 四、离线部署方案
#### 1、适用场景
服务器不能访问公网镜像仓库，部署包中需要包含应用镜像和基础组件镜像，或服务器已提前从内网仓库/离线介质加载这些镜像。Docker Compose 离线部署不要使用 `deploy-server.sh all`，因为 `all` 会主动执行 `pull`。离线部署应加载镜像后执行 `deploy-server.sh start`。

#### 2、环境要求
* Docker 20 or later
* Docker Compose 1.28 or later，或 Docker Compose v2
* bash
* curl（用于启动后的健康检查）
* 已准备应用镜像：`studio-console`、`studio-manager`、`studio-service`、`studio-runtime`
* 已准备基础组件镜像：MySQL、Redis、MinIO、MinIO Client

#### 3、安装步骤
##### 步骤 1、解压安装包：

```bash
tar -zxvf AgentBuilder.tar.gz
```

##### 步骤 2、加载离线镜像
加载应用镜像：

```bash
cd image
docker load -i studio-console_*.tar
docker load -i studio-manager_*.tar
docker load -i studio-service_*.tar
docker load -i studio-runtime_*.tar
```

加载基础组件镜像。镜像包名以实际离线包为准：

```bash
docker load -i mysql_*.tar
docker load -i redis_*.tar
docker load -i minio_*.tar
docker load -i minio-mc_*.tar
```

加载后用 `docker images` 确认镜像名和 tag。

##### 步骤 3、配置离线镜像
编辑 `compose/.env.server`：

```bash
cd ../compose
vi .env.server
```

将应用镜像源改为 `custom`，并关闭应用镜像拉取。`APP_IMAGE_PULL_POLICY` 只作用于 `studio-console`、`studio-manager`、`studio-service`、`studio-runtime` 四个应用镜像，不影响 MySQL、Redis、MinIO、MinIO Client：

```env
IMAGE_SOURCE=custom
APP_IMAGE_PULL_POLICY=never

STUDIO_CONSOLE_IMAGE=studio-console:<tag>
STUDIO_MANAGER_IMAGE=studio-manager:<tag>
STUDIO_SERVICE_IMAGE=studio-service:<tag>
STUDIO_RUNTIME_IMAGE=studio-runtime:<tag>
```

如果离线基础组件镜像的名称或 tag 不是默认值，也需要同步修改：

```env
MYSQL_IMAGE=mysql:8.0
REDIS_IMAGE=redis:7
MINIO_IMAGE=minio/minio:latest
MINIO_MC_IMAGE=minio/mc:latest
```

基础组件镜像在 `docker-compose-server.yml` 中固定使用 `pull_policy: if_not_present`。离线环境需要确保这些镜像已经提前加载到本机；如果本机不存在，Compose 会尝试查找/拉取并失败。

##### 步骤 4、修改服务配置
继续检查 `.env.server` 中的数据库、Redis、MinIO、端口和 TLS 配置。单机 Docker Compose 部署默认会启动内置 MySQL、Redis、MinIO。

##### 步骤 5、启动服务
离线部署不要执行 `./deploy-server.sh all`。执行：

```bash
./deploy-server.sh start
```

`start` 会执行基础初始化、启动全部服务、等待容器健康/运行状态，并验证以下地址：

```text
http://localhost/openjiuwen/
http://localhost/actuator/health
http://localhost:31113/v1/health
```

如需单独初始化基础数据库和对象存储，可执行：

```bash
./deploy-server.sh init-db
```

##### 步骤 6、安装后验证
在浏览器中输入以下地址并访问：

```text
http://节点ip/openjiuwen/#/home/overview
```

也可以使用脚本查看状态或日志：

```bash
./deploy-server.sh status
./deploy-server.sh logs
./deploy-server.sh verify
```

常用脚本命令：

离线环境下不要执行 `pull`、`all`、`update`，这些命令会尝试拉取镜像。离线启动使用 `start`。

| 命令 | 作用 |
|------|------|
| `./deploy-server.sh infra` | 启动 MySQL、Redis、MinIO，并执行 `init-db` |
| `./deploy-server.sh init-db` | 重新执行基础初始化和 MinIO bucket 初始化 |
| `./deploy-server.sh start` | 启动服务并验证，不主动拉取镜像 |
| `./deploy-server.sh all` | 拉取镜像、初始化、启动服务并验证 |
| `./deploy-server.sh update` | 拉取镜像、重启应用服务并验证 |
| `./deploy-server.sh verify` | 只执行 HTTP 验证 |
| `./deploy-server.sh status` | 查看容器状态 |
| `./deploy-server.sh logs [service]` | 查看全部或指定服务日志 |
| `./deploy-server.sh stop` | 停止并移除本部署的容器和网络 |

#### 7、K8s 离线部署（可选）
##### 7.1 环境要求
* 推荐使用Kubernetes v1.32版本

##### 7.2 安装流程
![k8sInstall.png](images/k8sInstall.png)

##### 7.3 安装步骤
###### 步骤 1、解压安装包：
tar -zxvf AgentBuilder.tar.gz

###### 步骤 2、加载镜像（需要替换为实际镜像压缩包名，每个节点都需要加载）
`cd image`

`docker load -i studio-manager_*.tar`

`docker load -i studio-service_*.tar`

`docker load -i studio-runtime_*.tar`

`docker load -i studio-console_*.tar`

###### 步骤 3、初始化数据库
在数据库执行init.sql

###### 步骤 4、修改yaml配置
`cd k8s`
###### 修改 studio-manager.yaml
`vim studio-manager.yaml`
* 修改镜像信息：将spec.template.spec.containers.image的值改为studio-manager 的镜像信息（格式IMAGE:TAG）
* 修改服务环境变量：spec.template.spec.containers.env（根据注释提示进行配置）

###### 修改 studio-service.yaml
`vim studio-service.yaml`
* 修改镜像信息：将spec.template.spec.containers.image的值改为studio-service 的镜像信息（格式IMAGE:TAG）
* 修改服务环境变量：spec.template.spec.containers.env（根据注释提示进行配置）

###### 修改 studio-runtime.yaml
`vim studio-runtime.yaml`
* 修改镜像信息：将spec.template.spec.containers.image的值改为studio-runtime 的镜像信息（格式IMAGE:TAG）
* 修改服务环境变量：spec.template.spec.containers.env（根据注释提示进行配置）

###### 修改 studio-console.yaml
`vim studio-console.yaml`
* 修改镜像信息：将spec.template.spec.containers.image的值改为studio-console 的镜像信息（格式IMAGE:TAG）

###### 步骤 5、启动服务
`cd k8s`
###### 启动studio-manager
`kubectl apply -f studio-manager.yaml`

###### 启动studio-service
`kubectl apply -f studio-service.yaml`

###### 启动studio-runtime
`kubectl apply -f studio-runtime.yaml`

###### 启动studio-console
`kubectl apply -f studio-console.yaml`

###### 步骤 6、安装后验证
在浏览器中输入以下地址并访问：
http://节点ip:30001/openjiuwen/#/home/overview
