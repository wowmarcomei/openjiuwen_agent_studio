# 本地开发指南

本文档介绍如何在本地搭建 Agent Studio 开发环境，使用 Trae IDE 进行调试开发。

---

## 1. 环境要求

| 工具 | 版本要求 |
|------|---------|
| JDK | 17+ |
| Python | 3.10+ |
| Node.js | 18+ |
| pnpm | 8+ |
| Docker | 20+（用于基础设施服务） |
| Git | 2.x |

---

## 2. 基础设施服务

本地开发需要启动 MySQL、Redis、MinIO 三个基础设施服务。推荐使用 Docker Compose 方式启动。

### 2.1 启动基础设施

在 WSL2 或 Linux 环境下执行：

```bash
cd docker/compose
# 先配置 .env.server（参考 .env.server.example）
./deploy-server.sh infra
```

该命令会启动以下服务：

| 服务 | 端口 | 说明 |
|------|------|------|
| MySQL | 3306 | 数据库，库名 `agent-builder` |
| Redis | 6379 | 缓存 |
| MinIO | 9000 (API) / 9001 (Console) | 对象存储，Bucket: `agent-builder` |

默认账号密码：
- MySQL: `root / 123456`
- MinIO: `minioadmin / minioadmin`

### 2.2 初始化数据库

首次启动需要初始化数据库表结构，执行：

```bash
./deploy-server.sh init-db
```

## 3. 后端服务（Java）

项目包含两个 Spring Boot 服务，通过 Trae 的 **Run and Debug** 面板启动。

### 3.1 配置说明

在 `.vscode/launch.json` 中已预置了启动配置，包含必要的环境变量：

- `SPRING_PROFILES_ACTIVE`: 激活对应的 Spring Profile（`manager` 或 `runtime`）
- `spring_datasource_url`: 数据库连接
- `redis_host` / `redis_port`: Redis 连接
- `obs_*`: MinIO 对象存储配置

### 3.2 启动 Manager 服务（31111）

1. 在 Trae 左侧点击 **Run and Debug** 图标
2. 从下拉菜单选择 **Studio Manager (31111)**
3. 点击运行按钮（绿色三角）

启动成功后日志会显示类似：
```
Started Application in X.XXs
```

### 3.3 启动 Runtime 服务（31113）

Manager 启动成功后，用同样方式启动 Runtime：

1. 从下拉菜单选择 **Studio Runtime Service (31113)**
2. 点击运行按钮

> **注意**：Runtime 服务依赖 Manager 服务，请确保 Manager 已启动成功。

## 4. Python Runtime

### 4.1 创建虚拟环境

```bash
cd agent-runtime
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### 4.2 安装依赖

```bash
pip install -r requirements.txt
```

### 4.3 配置环境变量

复制并编辑 `.env` 文件：

```bash
cp .env.example .env
```

关键配置项（本地开发默认值）：

```env
SERVER_HOST=127.0.0.1
SERVER_PORT=8000
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
MODEL_ROUTER_API=http://localhost:31113/v1/agent-builder
DATASOURCE_OBS_SERVER=http://localhost:9000
DATASOURCE_OBS_BUCKET=agent-builder
DATASOURCE_OBS_AK=minioadmin
DATASOURCE_OBS_SK=minioadmin
```

### 4.4 在 Trae 中启动

1. 从下拉菜单选择 **Python Runtime (8000)**
2. 点击运行按钮

> **注意**：`cwd` 配置为 `agent-runtime/agent_runtime`，以确保模块导入路径正确。

## 5. 前端

### 5.1 安装依赖

```bash
cd frontend
pnpm install
```

### 5.2 创建 .staging 目录

前端开发模式需要 `.staging` 目录，包含以下文件：

```bash
cd frontend
mkdir .staging
```

**文件 1：`.staging/index.html`**（开发模式入口 HTML）

```html
<!DOCTYPE html>
<html lang="en">
<head>
  <meta charset="utf-8" />
  <title>Open Jiuwen</title>
  <meta name="viewport" content="width=device-width, initial-scale=1" />
</head>
<body>
<script>
  const baseTag = document.getElementsByTagName('base')[0];
  window.AppWebPath = baseTag?.getAttribute('href') || '/';
  window.CDNAddress = '';
  window.pocVersion = 'version_placeholder';
  window.user = 'user_placeholder';
</script>

<div id="J_container">
  <root></root>
</div>
</body>
</html>
```

**文件 2：`.staging/proxy.json`**（API 代理配置）

将请求转发到后端各服务：

```json
{
  "/agent-manager": {
    "target": "http://localhost:31111",
    "secure": false,
    "changeOrigin": true
  },
  "/agent-runtime": {
    "target": "http://localhost:31113",
    "secure": false,
    "changeOrigin": true
  },
  "/mgmtconsole": {
    "target": "http://localhost:31111",
    "secure": false,
    "changeOrigin": true
  },
  "/model-router-strategies": {
    "target": "http://localhost:31111",
    "secure": false,
    "changeOrigin": true
  }
}
```

### 5.3 启动开发服务器

```bash
cd frontend
pnpm start
```

## 6. 服务启动顺序

建议按以下顺序启动各服务：

```
1. 基础设施（MySQL、Redis、MinIO）
      ↓
2. Studio Manager (31111)
      ↓
3. Studio Runtime Service (31113)  ← 依赖 Manager
      ↓
4. Python Runtime (8000)           ← 依赖 Runtime Service
      ↓
5. 前端开发服务器
```

## 8. 常见问题

### Q: Manager 启动报 `RedisClient` bean 未找到

确保 `launch.json` 中配置了 `SPRING_PROFILES_ACTIVE=manager`，以激活 Manager 专属的 Spring Profile。

### Q: Python Runtime 报 `No module named 'EIStart_base'`

确保 `launch.json` 中 Python Runtime 配置的 `cwd` 为 `${workspaceFolder}/agent-runtime/agent_runtime`。

### Q: 前端启动报 `Proxy configuration file not found`

确保 `frontend/.staging/proxy.json` 文件存在且内容正确。

### Q: WSL2 与 Windows 文件系统同步导致文件丢失

在 WSL2 中操作 Windows NTFS 分区上的 Git 仓库时，可能出现文件被标记为删除的情况。可通过以下命令恢复：

```bash
git restore <丢失的目录/>
# 或
git checkout -- <丢失的目录/>
```

### Q: Manager 启动报定时任务 `cleanObsObjects` 错误

该错误为非关键错误，不影响主服务运行，可安全忽略。
