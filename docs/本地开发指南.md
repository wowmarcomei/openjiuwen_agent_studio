# 本地开发指南

本文档介绍如何在本地搭建 Agent Studio 开发环境，使用 Trae IDE 进行调试开发。

---

## 1. 环境要求

| 工具 | 版本要求 |
|------|---------|
| JDK | 17+ |
| Python | 3.10+ |
| Node.js | 18+ |
| pnpm | 8+ |
| Docker | 20+（用于基础设施服务） |
| Git | 2.x |

---

## 2. 基础设施服务

本地开发需要启动 MySQL、Redis、MinIO 三个基础设施服务。推荐使用 `docker/compose/deploy-server.sh` 启动，脚本会统一使用 `docker-compose-server.yml` 和 `.env.server`。

### 2.1 检查 Compose 配置

进入 Compose 目录后先检查 `.env.server`：

```bash
cd docker/compose
vi .env.server
```

如果只启动基础设施（MySQL、Redis、MinIO），通常不需要改应用镜像配置，默认值即可。脚本会固定使用 `docker-compose-server.yml` 和 `.env.server`，不会误用同目录下的 `docker-compose.yml`。

如果要通过 `./deploy-server.sh all` 启动完整 Docker 环境，需要确认 `.env.server` 中的 `IMAGE_SOURCE`。默认使用 GitHub Container Registry：

```env
IMAGE_SOURCE=ghcr
IMAGE_TAG=latest
GHCR_IMAGE_REPOSITORY=ghcr.io/wowmarcomei/openjiuwen_agent_studio
```

如需切换到 Docker Hub：

```env
IMAGE_SOURCE=dockerhub
IMAGE_TAG=latest
DOCKERHUB_IMAGE_REPOSITORY=wowmarcomei/openjiuwen_agent_studio
```

GitHub 镜像格式为 `ghcr.io/wowmarcomei/openjiuwen_agent_studio/<service>:<tag>`；Docker Hub 镜像格式为 `wowmarcomei/openjiuwen_agent_studio:<service>-<tag>`。

如果要使用内部私有镜像仓库，可设置 `IMAGE_SOURCE=custom`，并在 `.env.server` 中填写 `STUDIO_CONSOLE_IMAGE`、`STUDIO_MANAGER_IMAGE`、`STUDIO_SERVICE_IMAGE`、`STUDIO_RUNTIME_IMAGE`。

### 2.2 启动基础设施

在 WSL2 或 Linux 环境下执行：

```bash
cd docker/compose
./deploy-server.sh infra
```

该命令会启动以下服务，并执行 `init-db`：

| 服务 | 端口 | 说明 |
|------|------|------|
| MySQL | 3306 | 数据库，库名 `agent-builder` |
| Redis | 6379 | 缓存 |
| MinIO | 9000 (API) / 9001 (Console) | 对象存储，Bucket: `agent-builder` |

默认账号密码：
- MySQL: `root / 123456`
- MinIO: `minioadmin / minioadmin`

### 2.3 初始化数据库和对象存储

如需单独重新执行基础初始化：

```bash
./deploy-server.sh init-db
```

`init-db` 会在 MySQL 容器内执行 `docker/init.sql`，并确保 MinIO bucket 存在。Manager 和 Runtime Service 的业务表结构由各自 Spring Boot 应用启动时的 `spring.sql.init` 配置执行。

### 2.4 一键启动完整环境

如需直接拉取镜像、执行基础初始化、启动全部服务并做启动后验证：

```bash
./deploy-server.sh all
```

脚本会先执行幂等的 `init-db`，再在 `up -d` 后等待容器健康/运行状态，并实际检查：

```text
http://localhost/openjiuwen/
http://localhost/actuator/health
http://localhost:31113/v1/health
```

如果端口或反向代理路径有调整，可在 `.env.server` 中覆盖 `FRONTEND_URL`、`NGINX_HEALTH_URL`、`KEY_API_URL`。

常用脚本命令：

| 命令 | 作用 |
|------|------|
| `./deploy-server.sh infra` | 只启动 MySQL、Redis、MinIO，并执行 `init-db` |
| `./deploy-server.sh init-db` | 重新执行基础初始化和 MinIO bucket 初始化 |
| `./deploy-server.sh start` | 启动完整 Docker 环境并验证，不主动拉取镜像 |
| `./deploy-server.sh all` | 拉取镜像、初始化、启动完整 Docker 环境并验证 |
| `./deploy-server.sh stop` | 停止并移除本部署的容器和网络 |
| `./deploy-server.sh logs [service]` | 查看全部或指定服务日志 |

## 3. 后端服务（Java）

项目包含两个 Spring Boot 服务，通过 Trae 的 **Run and Debug** 面板启动。

### 3.1 配置说明

在 `.vscode/launch.json` 中已预置了启动配置，包含必要的环境变量：

- `SPRING_PROFILES_ACTIVE`: 激活对应的 Spring Profile（`manager` 或 `runtime`）
- `spring_datasource_url`: 数据库连接
- `redis_host` / `redis_port`: Redis 连接
- `obs_*`: MinIO 对象存储配置

### 3.2 启动 Manager 服务（31111）

1. 在 Trae 左侧点击 **Run and Debug** 图标
2. 从下拉菜单选择 **Studio Manager (31111)**
3. 点击运行按钮（绿色三角）

启动成功后日志会显示类似：
```
Started Application in X.XXs
```

### 3.3 启动 Runtime 服务（31113）

Manager 启动成功后，用同样方式启动 Runtime：

1. 从下拉菜单选择 **Studio Runtime Service (31113)**
2. 点击运行按钮

> **注意**：Runtime 服务依赖 Manager 服务，请确保 Manager 已启动成功。

## 4. Python Runtime

### 4.1 创建虚拟环境

```bash
cd agent-runtime
python -m venv .venv

# Windows
.venv\Scripts\activate

# Linux / macOS
source .venv/bin/activate
```

### 4.2 安装依赖

```bash
pip install -r requirements.txt
```

### 4.3 配置环境变量

复制并编辑 `.env` 文件：

```bash
cp .env.example .env
```

关键配置项（本地开发默认值）：

```env
SERVER_HOST=127.0.0.1
SERVER_PORT=8000
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
MODEL_ROUTER_API=http://localhost:31113/v1/agent-builder
DATASOURCE_OBS_SERVER=http://localhost:9000
DATASOURCE_OBS_BUCKET=agent-builder
DATASOURCE_OBS_AK=minioadmin
DATASOURCE_OBS_SK=minioadmin
```

### 4.4 在 Trae 中启动

1. 从下拉菜单选择 **Python Runtime (8000)**
2. 点击运行按钮

> **注意**：`cwd` 配置为 `agent-runtime/agent_runtime`，以确保模块导入路径正确。

## 5. 前端

### 5.1 安装依赖

```bash
cd frontend
pnpm install
```

### 5.2 检查 .staging 配置

`.staging` 是前端工程的受控配置目录，已经随代码提交，不需要手工创建。Angular 构建入口使用 `frontend/.staging/index.html`，开发服务器代理使用 `frontend/.staging/proxy.json`。

当前 `ng serve` 在 `angular.json` 中显式引用 `frontend/.staging/proxy.json`，所以该文件是本地前端开发所需的代理配置。默认代理会把 `/v1`、`/v2` 转发到本机 `http://localhost`，也就是 Docker Compose 启动的 `studio-console` Nginx 网关：

```json
{
  "/v1": {
    "target": "http://localhost",
    "changeOrigin": true,
    "ws": true,
    "secure": false
  },
  "/v2": {
    "target": "http://localhost",
    "changeOrigin": true,
    "ws": true,
    "secure": false
  }
}
```

这里配置 `/v1`、`/v2` 是正确的。前端实际请求路径通常是 `/v1/{projectId}/agent-manager/...`、`/v1/{projectId}/agent-runtime/...`、`/v2/...`，`/agent-manager` 和 `/agent-runtime` 不是一级入口。生产 Nginx 也是先接住 `/v1`、`/v2`，再按更细的路径分发到 `studio-manager` 或 `studio-service`。

如果使用 `./deploy-server.sh all` 启动完整 Docker 环境，保持默认值即可。如果只用 `./deploy-server.sh infra` 启动基础设施，然后在 IDE 中本地启动 Java 后端，本机没有 `studio-console` Nginx 网关，单纯把 `/v1`、`/v2` 指向 `31111` 或 `31113` 都不能完整模拟生产路由。此时建议额外启动一个本地网关，或临时维护一份按接口路径分流到 `31111`、`31113` 的 proxy 配置。

### 5.3 启动开发服务器

```bash
cd frontend
pnpm start
```

## 6. 服务启动顺序

建议按以下顺序启动各服务：

```
1. 基础设施（MySQL、Redis、MinIO）
      ↓
2. Studio Manager (31111)
      ↓
3. Studio Runtime Service (31113)  ← 依赖 Manager
      ↓
4. Python Runtime (8000)           ← 依赖 Runtime Service
      ↓
5. 前端开发服务器
```

## 8. 常见问题

### Q: Manager 启动报 `RedisClient` bean 未找到

确保 `launch.json` 中配置了 `SPRING_PROFILES_ACTIVE=manager`，以激活 Manager 专属的 Spring Profile。

### Q: Python Runtime 报 `No module named 'EIStart_base'`

确保 `launch.json` 中 Python Runtime 配置的 `cwd` 为 `${workspaceFolder}/agent-runtime/agent_runtime`。

### Q: 前端启动报 `Proxy configuration file not found`

确保仓库中的 `frontend/.staging/proxy.json` 未被误删。如果代理连接失败，检查其中的 `target` 是否指向正在运行的 Nginx/后端网关。

### Q: WSL2 与 Windows 文件系统同步导致文件丢失

在 WSL2 中操作 Windows NTFS 分区上的 Git 仓库时，可能出现文件被标记为删除的情况。可通过以下命令恢复：

```bash
git restore <丢失的目录/>
# 或
git checkout -- <丢失的目录/>
```

### Q: Manager 启动报定时任务 `cleanObsObjects` 错误

该错误为非关键错误，不影响主服务运行，可安全忽略。
