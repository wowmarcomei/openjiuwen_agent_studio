## 一、概述

openJiuwen AgentStudio 包含以下 4 个服务组件：

| 服务 | 技术栈 | 默认端口 | 说明 |
|------|--------|----------|------|
| studio-console | Nginx + Angular | 80（HTTP）/ 443（HTTPS） | 前端控制台，提供Web界面和反向代理 |
| studio-manager | Spring Boot (Java 17) | 31111 | Agent管理服务，负责CRUD、工作流编排、知识库管理 |
| studio-service | Spring Boot (Java 17) | 31113 | Agent运行时服务，负责Agent执行、事件处理、MCP支持 |
| studio-runtime | Python (FastAPI + Uvicorn) | 31014 | Python Agent运行时引擎，负责IR解析、工作流执行 |

## 二、环境要求

### 2.1 硬件要求

| 资源 | 最低体验配置 | 推荐配置 | K8s集群配置（双实例） |

| CPU | 4核 | 8核 | 16核 |
| 内存 | 8GB | 16GB | 32GB |
| 磁盘 | 50GB | 100GB | 200GB |

各服务资源分配参考（Docker部署）：

| 服务 | CPU | 内存 |
|------|-----|------|
| studio-console | 0.5核 | 512MB |
| studio-manager | 2核 | 4GB |
| studio-service | 2核 | 4GB |
| studio-runtime | 2核 | 4GB |

各服务资源分配参考（K8s部署，双实例）：

| 服务 | 实例数 | 单实例CPU | 单实例内存 | 总CPU | 总内存 |
|------|--------|----------|-----------|-------|--------|
| studio-console | 1 | 0.25核 | 512MB | 0.25核 | 512MB |
| studio-manager | 2 | 2核 | 4GB | 4核 | 8GB |

> K8s部署时studio-console通常只需1个实例（Nginx无状态反向代理），其余服务建议至少2个实例以保证高可用。资源配额来源于各服务的K8s YAML配置。

### 2.2 软件要求

| 软件 | 版本要求 | 说明 | 环境检查 |
|------|----------|------|----------|
| Docker | 19.03+ | 容器运行时 | `docker --version` |
| Docker Compose 或 Kubernetes | 1.28+ / v1.32（推荐） | 单机部署选Docker Compose，集群部署选Kubernetes，二选一 | `docker compose version` / `kubectl version --client` |

### 2.3 第三方组件依赖

以下组件需自行部署，安装配置方法请参考各组件官方文档，本文档不再赘述。2.1节中的硬件资源要求不包含第三方组件所需资源，请根据实际部署规模额外规划。

| 组件 | 是否必需 | 版本要求 | 默认端口 | 说明 |
|------|----------|----------|----------|------|
| MySQL / GaussDB | **必需** | MySQL 8.0+ | 3306 | 数据库，数据库名可自定义。默认驱动为 `org.mariadb.jdbc.Driver`（MySQL），切换GaussDB需修改环境变量 `spring_datasource_driver_class_name` 为GaussDB驱动类 |

| 对象存储（OBS / MinIO） | **必需** | - | - | 对象存储，用于IR文件和用户文件 |

## 四、初始化数据与存储

创建数据库并授权，表结构由 studio-manager 和 studio-service 首次启动时自动创建。

> 数据库名可自定义（下方示例使用 `agent_studio`），JDBC 连接串中的数据库名必须与实际创建的数据库名一致。

**MySQL**：

```sql
CREATE DATABASE IF NOT EXISTS `agent_studio` CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;
GRANT ALL PRIVILEGES ON `agent_studio`.* TO 'root'@'%' WITH GRANT OPTION;
FLUSH PRIVILEGES;
```

**GaussDB**：

> GaussDB 无需额外创建 schema，`DBCOMPATIBILITY = 'M'` 兼容 MySQL 语法，表结构由应用自动创建。GaussDB无需执行GRANT语句，使用安装时设置的超级用户即可访问。

```sql
CREATE DATABASE agent_studio TEMPLATE = templatem ENCODING 'UTF8' DBCOMPATIBILITY = 'M';
```

验证数据库创建成功：

**MySQL**：

```sql
SHOW DATABASES LIKE 'agent_studio';
```

**GaussDB**：

```sql
SELECT datname FROM pg_database WHERE datname = 'agent_studio';
```

确认数据库时区：

```sql
-- MySQL
SELECT NOW(), @@time_zone;

-- GaussDB
SELECT NOW(), current_setting('TIMEZONE');
```

> 数据库时区需与部署环境一致，否则会导致定时任务执行时间偏差、数据记录时间戳不准确等问题。若时区不正确，可通过以下方式修改：
>
> - MySQL临时修改（重启失效）：`SET GLOBAL time_zone = '+8:00';`
> - MySQL永久修改：在MySQL配置文件 `my.cnf` 中添加 `default-time-zone = '+8:00'`
> - GaussDB修改：在 `postgresql.conf` 中添加 `timezone = 'Asia/Shanghai'`

### 创建对象存储桶

在 OBS/MinIO 中创建桶，后续配置中的 `obs_bucket` 需填写此处创建的桶名。

**MinIO 示例**：

**方式一**：登录 MinIO 控制台（默认 `http://<MINIO_IP>:9001`），创建桶。

**方式二**：使用 mc 命令行：

```bash
# 添加MinIO服务别名，<MINIO_IP>、<ACCESS_KEY>、<SECRET_KEY>替换为实际值
mc alias set myminio http://<MINIO_IP>:9000 <ACCESS_KEY> <SECRET_KEY>
# 创建桶，agent-builder为示例桶名
mc mb myminio/agent-builder
```

## 五、基于Docker Compose安装

### 5.1 安装流程

![dockerComposeInstall.png](images/dockerComposeInstall.png)

### 5.2 安装步骤

#### 步骤 1：解压安装包

```bash
tar -zxvf AgentBuilder.tar.gz
```

#### 步骤 2：加载镜像

镜像压缩包位于解压目录的 `image/` 下：

```bash
cd image

docker load -i studio-manager_*.tar
docker load -i studio-service_*.tar
docker load -i studio-runtime_*.tar
docker load -i studio-console_*.tar
```

验证镜像加载成功：

```bash
docker images
```

预期输出包含以下4个镜像：

| REPOSITORY | TAG |
|------------|-----|
| studio-manager | {版本号}.{构建架构} |
| studio-service | {版本号}.{构建架构} |
| studio-runtime | {版本号}.{构建架构} |
| studio-console | {版本号}.{构建架构} |

> 构建架构由运行环境决定，如 `x86_64`、`aarch64` 等。

#### 步骤 3：初始化数据库

参见[第四章](#四初始化数据与存储)。

#### 步骤 4：修改环境配置

复制解压目录下 `compose/.env.example` 为 `.env`，然后编辑 `.env` 填写必填项（镜像、数据库、Redis、对象存储）。所有配置项的详细说明、默认值和可选配置请参考 `.env.example` 中的注释。

> HTTPS 启动和 Redis 集群/哨兵配置详见 `.env.example` 中对应分区注释。

```bash
cd compose
cp .env.example .env
vi .env
```

#### 步骤 5：启动服务

启动服务：

```bash
docker compose up -d
```

查看服务状态：

```bash
docker compose ps
```

> 默认使用 Docker Compose V2 命令（`docker compose`）。若环境为 V1 版本，请将 `docker compose` 替换为 `docker-compose`。

预期输出：

| 服务 | 状态 | 端口 |
|------|------|------|
| studio-console | Up | 0.0.0.0:80->80/tcp |
| studio-manager | Up | 0.0.0.0:31111->31111/tcp |
| studio-service | Up | 0.0.0.0:31113->31113/tcp |
| studio-runtime | Up | 0.0.0.0:31014->31014/tcp |

#### 步骤 6：安装后验证

参见[第七章](#七安装后验证)。

## 六、基于K8s安装

### 6.1 安装流程

![k8sInstall.png](images/k8sInstall.png)

### 6.2 安装步骤

#### 步骤 1：解压安装包

```bash
tar -zxvf AgentBuilder.tar.gz
```

#### 步骤 2：加载镜像

每个K8s节点都需要加载镜像，镜像压缩包位于解压目录的 `image/` 下：

```bash
cd image

docker load -i studio-manager_*.tar
docker load -i studio-service_*.tar
docker load -i studio-runtime_*.tar
docker load -i studio-console_*.tar
```

#### 步骤 3：初始化数据库

参见[第四章](#四初始化数据与存储)。

#### 步骤 4：修改YAML配置

在解压目录的 `k8s/` 下修改各服务的YAML配置，修改 `spec.template.spec.containers.env` 中的必填项。各环境变量的详细说明和默认值请参考 YAML 中的注释。

> HTTPS 启动和 Redis 集群/哨兵配置详见各 YAML 中对应注释。

> **重要**：每个 YAML 文件中标记为 `[必填]` 的环境变量必须配置，`[选填]` 项默认值通常无需修改。

- **studio-manager.yaml** — 修改镜像信息，填写数据库、Redis、OBS 必填项
- **studio-service.yaml** — 修改镜像信息，填写数据库、Redis、OBS 必填项
- **studio-runtime.yaml** — 修改镜像信息，填写 Redis、OBS 必填项
- **studio-console.yaml** — 修改镜像信息

#### 步骤 5：启动服务

在解压目录的 `k8s/` 下按顺序启动各服务：

```bash
cd k8s
```

启动服务：

```bash
# 启动studio-manager
kubectl apply -f studio-manager.yaml

# 启动studio-service
kubectl apply -f studio-service.yaml

# 启动studio-runtime
kubectl apply -f studio-runtime.yaml

# 启动studio-console
kubectl apply -f studio-console.yaml
```

查看Pod状态：

```bash
kubectl get pods
```

预期所有Pod状态为 `Running`。

#### 步骤 6：安装后验证

参见[第七章](#七安装后验证)。

## 八、常见问题

### 8.1 服务启动失败：数据库连接异常

**现象**：studio-manager 或 studio-service 日志报 `Communications link failure` 或 `Access denied`。

**排查步骤**：

1. 确认数据库已创建：`SHOW DATABASES LIKE 'agent_studio';`
2. 确认 `SPRING_DATASOURCE_URL` 中IP和端口可达：`telnet <MYSQL_IP> 3306`
3. 确认用户名密码正确：`mysql -u root -p -h <MYSQL_IP>`
4. 确认表结构已自动创建：`USE <数据库名>; SHOW TABLES;`

### 8.2 服务启动失败：Redis连接异常

**现象**：服务日志报 `Unable to connect to Redis`。

**排查步骤**：

1. 确认Redis服务运行中：`redis-cli -h <REDIS_IP> -p 6379 ping`
2. 确认 `REDIS_HOST` 和 `REDIS_PORT` 配置正确
3. 如有密码，确认 `REDIS_PASSWORD` 已配置

### 8.3 服务启动失败：OBS连接异常

**现象**：studio-runtime 日志报 OBS 相关错误。

**排查步骤**：

1. 确认OBS服务可达：`curl -k <OBS_URL>`
2. 确认AK/SK配置正确
3. 确认桶已创建且AK/SK有读写权限

### 8.4 studio-runtime无法调用LLM模型

**现象**：Agent对话无响应或报模型调用错误。

**排查步骤**：

1. 确认 `MODEL_ROUTER_API` 配置正确
2. 确认studio-service可访问：`curl http://<IP>:31113/v1/agent-builder`
3. 确认模型服务已正确配置

### 8.5 前端页面无法访问后端API

**现象**：前端页面打开但接口请求404或502。

**排查步骤**：

1. 确认Nginx反向代理配置正确（`docker/compose/config/nginx.conf`）
2. 确认studio-manager和studio-service服务正常运行

### 8.6 Docker镜像加载失败

**现象**：`docker load` 报错 `no space left on device`。

**解决方法**：

```bash
# 清理无用的Docker资源
docker system prune -a

# 查看磁盘使用
df -h
```
