# 安装部署指南

## 一、概述

openJiuwen AgentStudio 包含 4 个应用服务，通过 Docker Compose 编排部署：

| 服务 | 技术栈 | 默认端口 | 说明 |
|------|--------|----------|------|
| studio-console | Nginx + Angular | 80 | 前端控制台 + API 反向代理 |
| studio-manager | Spring Boot (Java 17) | 31111 | 管理面：Agent/知识库/模型/工具/MCP 管理 |
| studio-service | Spring Boot (Java 17) | 31113 | 执行面：Agent 执行/对话/模型调用/知识检索 |
| studio-runtime | Python (FastAPI) | 31014 | 编排引擎：工作流/LLM/MCP/记忆 |

部署方案内置基础设施（MySQL、Redis、MinIO），无需提前部署外部依赖。也支持使用外部基础设施。编排文件包含 8 个服务：

| 类型 | 服务 | 说明 |
|------|------|------|
| 基础设施 | mysql、redis、minio、minio-init | 由 `deploy.sh` 自动启动和初始化 |
| 应用服务 | studio-console、studio-manager、studio-service、studio-runtime | 业务服务 |

| 依赖 | 版本 | 必选 | 说明 |
|------|------|------|------|
| MySQL / GaussDB | 8.0+ | ✅ | 主数据存储。默认驱动 `org.mariadb.jdbc.Driver`，GaussDB 需改为 `com.huawei.opengauss.jdbc.Driver` |
| Redis | 7.x | ✅ | 缓存/会话/变量存储，支持单机/集群/哨兵模式 |
| MinIO / OBS | latest | ✅ | 对象存储 |
| OpenSearch | 2.x | ❌ | 记忆库向量存储，启用记忆库时必需 |

> ⚠️ **命名说明**：Docker 中 `studio-service` 容器装的是 Java `studio-runtime` 模块的 JAR；`studio-runtime` 容器装的是 Python `agent-runtime` 服务。请勿混淆。

> 📁 **部署目录**：所有部署相关文件统一在 `deploy/` 目录下，使用同一套脚本和编排文件，在线/离线仅通过 `.env` 中的 `IMAGE_SOURCE` 区分。

## 二、环境要求

| 资源 | 最低配置 | 推荐配置 |
|------|---------|---------|
| CPU | 4核 | 8核 |
| 内存 | 8GB | 16GB |
| 磁盘 | 50GB | 100GB |

各服务资源分配：

| 服务 | CPU | 内存 |
|------|-----|------|
| studio-console | 0.5核 | 512MB |
| studio-manager | 2核 | 4GB |
| studio-service | 2核 | 4GB |
| studio-runtime | 2核 | 4GB |

> 本文档中 `<项目根目录>` 指项目 clone 的根目录，如 `/home/user/agent-studio`。

## 三、在线部署

> **适用场景**：部署机器可访问外网。
>
> **部署脚本**：`deploy/deploy.sh` — 一个脚本管理全生命周期。

```
步骤1              步骤2              步骤3              步骤4                步骤5
代码推送触发CI/CD → 安装依赖环境(首次) → clone代码+配置 → deploy.sh all → 浏览器访问
构建推送镜像       Docker+MySQL等      .env              拉镜像+拉起服务
```

### 步骤 1：代码推送触发 CI/CD 构建镜像

项目已配置 GitHub Actions（`.github/workflows/build-push-ghcr.yml`），代码推送到 `mxh_dev` 分支（举例，具体分支与 GitHub 中的 workflow 保持一致）后自动构建并推送 4 个镜像到 GHCR。

| 触发方式 | 镜像 tag |
|---------|---------|
| 推送到 mxh_dev（自动触发） | `latest` + `<分支>-<日期>-<sha>` |
| 手动触发 | Actions 页面点击 "Run workflow" |

CI/CD 前置：仓库 Settings → Actions → General → Workflow permissions 选择 **"Read and write permissions"**。

构建完成后在 Actions 日志末尾查看 4 个镜像地址。

### 步骤 2：安装依赖环境（首次部署）

> **仅首次部署需要**，后续部署跳过此步骤。

#### 2.1 安装 Docker

```bash
# CentOS
yum install -y yum-utils && yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo && yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Ubuntu/Debian
apt-get update && apt-get install -y ca-certificates curl && install -m 0755 -d /etc/apt/keyrings && curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null && apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

systemctl enable --now docker
```

验证：`docker --version && docker compose version`

#### 2.2 准备外部依赖

> 在线部署方案内置了 MySQL、Redis、MinIO 容器，首次运行 `deploy.sh all` 时会自动拉取并启动。**如果使用内置依赖，跳过此步骤。**

如需使用已有的外部依赖，请确保以下服务已部署且可达：

| 依赖 | 版本要求 | 说明 |
|------|---------|------|
| MySQL / GaussDB | 8.0+ | 需提前创建数据库（库名默认 `agent-builder`，utf8mb4） |
| Redis | 7.x | 支持单机/集群/哨兵模式 |
| MinIO / OBS | latest | 需提前创建 bucket（默认 `agent-builder`） |

使用外部依赖时，在步骤 3 的 `.env` 中填写对应的连接地址、端口和凭证即可。

### 步骤 3：获取代码并配置环境

```bash
# 克隆代码
git clone <仓库地址> && cd agent-studio

# 配置环境变量
cd deploy
cp .env.template .env
vi .env
```

**必填配置项**（`.env`）：

```bash
# 镜像来源（四选一：ghcr / dockerhub / offline / custom）
IMAGE_SOURCE=ghcr
IMAGE_TAG=latest

# GHCR 镜像仓库地址
GHCR_IMAGE_REPOSITORY=ghcr.io/<owner>/openjiuwen_agent_studio

# 私有镜像仓库登录凭证
GHCR_USERNAME=<USERNAME>
GHCR_TOKEN=<PAT>
```

> `offline` 和 `custom` 模式下还需配置 `STUDIO_*_IMAGE` 镜像名，离线包的 `.env.template` 会自动填好。

使用内置依赖时，数据库/Redis/MinIO 等配置项已在 `.env` 中预填默认值，一般无需修改。使用外部依赖时，需将对应地址和凭证替换为实际值。详见文件内注释。

### 步骤 4：一键部署

```bash
cd <项目根目录>/deploy
bash deploy.sh all
```

脚本自动执行：登录镜像仓库 → 拉取镜像 → 初始化基础设施（MySQL/Redis/MinIO + 数据库 + MinIO 桶） → 启动应用服务 → 健康检查 → 输出访问地址。

> `all` 命令会先拉取镜像再启动，适合**首次部署**。后续更新使用 `update`，重启使用 `restart`。

### 步骤 5：验证访问

浏览器访问：`http://<IP>/openjiuwen/`

## 四、离线部署

> **适用场景**：部署机器无法访问外网。
>
> **分两阶段**：有网机器准备离线包 → 目标机器部署。
>
> **部署脚本**：与在线部署使用同一个 `deploy.sh`，`.env` 中 `IMAGE_SOURCE=offline` 即可。

```
 第一阶段：有网机器                    第二阶段：目标机器
┌──────────────────────────┐        ┌──────────────────────────┐
│ 步骤1: 安装Docker        │        │ 步骤3: 离线安装Docker     │
│ 步骤2: 构建离线安装包    │──scp──▶│ 步骤4: 配置 .env          │
│   (自动包含依赖镜像)     │        │ 步骤5: deploy.sh all     │
└──────────────────────────┘        └──────────────────────────┘
```

### 第一阶段：有网机器

> **执行环境**：可访问外网的 Linux 机器。需 Docker；源码编译还需 JDK 17+、Maven 3.8+、Node.js 22+、pnpm。

#### 步骤 1：安装 Docker

> ⚠️ 此步骤需在线安装，请确保机器可访问外网。

```bash
# CentOS
yum install -y yum-utils && yum-config-manager --add-repo https://download.docker.com/linux/centos/docker-ce.repo && yum install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

# Ubuntu/Debian
apt-get update && apt-get install -y ca-certificates curl && install -m 0755 -d /etc/apt/keyrings && curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc && echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | tee /etc/apt/sources.list.d/docker.list > /dev/null && apt-get update && apt-get install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin

systemctl enable --now docker
```

#### 步骤 2：构建离线安装包

> **脚本路径**：`deploy/offline/prepare.sh`

```bash
cd <项目根目录>

# 默认版本号 1.0.0
bash deploy/offline/prepare.sh

# 指定版本号
VERSION=2.0.0 bash deploy/offline/prepare.sh
```

自动执行：拉取基础镜像 → 编译源码（如缺失）→ 构建4个应用镜像 → 导出应用镜像 tar → 拉取并导出依赖镜像（MySQL/Redis/MinIO/MC）→ 复制配置 + 辅助脚本 + 数据库初始化脚本 → 打包 `AgentBuilder-offline-<version>.tar.gz`。

**传输到目标机器**：

```bash
# 离线安装包（包含所有镜像和配置）
scp deploy/offline/AgentBuilder-offline-1.0.0.tar.gz user@target-host:~/

# Docker二进制包（目标机器未安装Docker时，提前下载）
# 下载地址：https://download.docker.com/linux/static/stable/x86_64/
scp docker-27.3.1.tgz user@target-host:~/
```

### 第二阶段：目标机器

#### 步骤 3：离线安装 Docker

如已安装 Docker（`docker --version`），跳过。

```bash
# 解压离线包
cd ~
tar -xzvf AgentBuilder-offline-1.0.0.tar.gz

# 安装 Docker（需 sudo）
sudo bash ~/AgentBuilder-offline-1.0.0/scripts/install-docker-offline.sh ~/docker-27.3.1.tgz
```

#### 步骤 4：配置环境变量

```bash
cd ~/AgentBuilder-offline-1.0.0
cp .env.template .env
vi .env
```

离线包的 `.env.template` 已自动完成以下配置，**一般无需修改**：
- `IMAGE_SOURCE=offline` 已设置
- `STUDIO_*_IMAGE` 已取消注释并填入实际镜像 tag
- 数据库/Redis/MinIO 默认值指向内置基础设施

使用外部基础设施时，需将数据库/Redis/MinIO 的地址和凭证替换为实际值。详见 `.env.template` 中的注释。

#### 步骤 5：一键部署

```bash
cd ~/AgentBuilder-offline-1.0.0
bash deploy.sh all
```

自动执行：加载镜像 → 初始化基础设施（MySQL/Redis/MinIO + 数据库 + MinIO 桶） → 启动应用服务 → 健康检查 → 输出访问地址。

> 与在线部署使用完全相同的命令，只是镜像来源不同（`docker load` 替代 `docker pull`）。

浏览器访问：`http://<IP>/openjiuwen/`


## 九、常见问题

### Q1: 数据库连接失败

**现象**：日志报 `Communications link failure` 或 `Access denied`

**排查**：
1. 确认数据库已创建：`SHOW DATABASES LIKE 'agent_builder';`
2. 确认 `.env` 中 IP 和端口可达：`telnet <MYSQL_IP> 3306`
3. Docker 中 MySQL 用宿主机 IP，不用 `127.0.0.1`
4. 获取 Docker 网桥 IP：`ip addr show docker0 | grep inet`

### Q2: Redis 连接失败

**现象**：日志报 `Unable to connect to Redis`

**排查**：
1. 确认 Redis 运行：`redis-cli -h <IP> -p 6379 ping`
2. 有密码需配 `REDIS_PASSWORD`
3. 集群/哨兵模式确认 `REDIS_MODE` 等配置正确

### Q3: 容器内无法访问宿主机服务

**现象**：容器内无法连接宿主机 MySQL/Redis/MinIO

**排查**：
1. `ip addr show docker0 | grep inet`（通常 `172.17.0.1`）
2. `.env` 中将 `127.0.0.1` 替换为该 IP

### Q4: studio-runtime 反复重启

**现象**：容器状态 Restarting

**排查**：
1. `docker compose logs studio-runtime` 查看日志
2. Python 服务启动必须连 Redis，Redis 不可达会直接失败
3. 检查 `REDIS_HOST` 是否用了 `127.0.0.1`

### Q5: 镜像拉取失败 / 403

**现象**：`docker pull ghcr.io/...` 报 403

**排查**：私有镜像需登录 `echo <PAT> | docker login ghcr.io -u <USER> --password-stdin`，PAT 需 `read:packages` 权限。或在 `.env` 中配置 `GHCR_USERNAME` 和 `GHCR_TOKEN` 后使用 `bash deploy.sh pull`。

### Q6: 端口冲突

**现象**：`bind: address already in use`

**排查**：`netstat -tlnp | grep -E '80|31111|31113|31014'`，在 `.env` 中修改冲突端口。

### Q7: 离线部署镜像加载失败

**现象**：`docker load` 报错

**排查**：
1. 确认 `.env` 中 `IMAGE_SOURCE=offline`
2. 确认 `images/` 和 `dep-images/` 目录下有 `.tar` 文件
3. 确认 `.env` 中 `STUDIO_*_IMAGE` 的 tag 与 tar 文件中的 tag 一致（`image_info.txt` 中有记录）
